# 콘텐츠 설계 상의 (content-design)

`phase-workflow`의 질문 양식·보고 양식·PR 절차를 함께 따른다. 이 스킬은 **2-0단계의 파일 하나를 만드는 방법**이다.

## 1. 준비 (토큰 절약)
1. `content/README.md`(인덱스)만 먼저 읽는다. 결정 순서와 각 파일의 상태가 있다.
2. 지금 만들 파일의 **앞 순서 파일은 "결정 요약"(맨 위 5줄)만** 읽는다. 전부 읽지 않는다.
3. `content/world.md`의 **글 톤 규칙**을 따른다: 짧고 건조한 서술체, 감정어·느낌표·현대어 금지, 수치는 괄호.

## 2. 상의
- **2-0단계에서는 질문 도구(AskUserQuestion)를 쓰지 않는다.** 사용자가 직접 정한다. (질문이 이어지면 흐름이 꼬인다는 사용자 요청)
- 대신 파일마다 **"필수 결정 목록"**을 먼저 보여 준다. 선택지나 추천은 붙이지 않고, 이미 확정된 것과 맞물리는 점만 한 줄로 알려 준다. 사용자가 항목별로 정해서 답한다.
- 사용자가 정한 내용을 **그대로 반영**한다. 우려가 있으면 보고에 한 번만 적는다.
- 반영 뒤에 **빠진 것이나 충돌**이 있을 때만 그때 짧게 묻는다 (질문은 최소로).

## 3. 파일 작성 규칙
- 맨 위에 **"결정 요약" 5줄 이내**.
- 아래는 표 중심. 논의 과정은 쓰지 않고 **확정 결과와 이유 한 줄**만.
- 항목마다 상태: 확정 / 제안 / 미정.
- 한 파일이 약 150줄을 넘으면 `events-1.md`, `events-2.md`처럼 나눈다.
- 규칙은 `GAME_DESIGN.md`가 기준이다. 여기에는 목록·수치·문구 같은 **콘텐츠**만 둔다.
- 구현된 뒤에는 `data/*.js`가 원본이고 문서에는 "구현됨"과 설계 의도만 남긴다.

## 4. 끝낼 때
- `content/README.md`의 상태를 갱신한다.
- `PLAN2.md`의 2-0 체크박스와 진행 기록, 필요하면 `GAME_DESIGN.md`(새 규칙)와 `HANDOFF.md`(현재 상태)를 갱신한다.
- 답변을 받으면 **바로 파일로 커밋·푸시**한다 (세션이 끊겨도 결정이 사라지지 않게).
- 파일 하나당 PR 하나. 사용자가 합친 뒤 다음 파일로 간다. 합치기 전이라면 같은 PR에 올리고 PR 본문을 갱신한다.
